# Career Direct Korea AI Marketing Engine 구현 계획

- 기준 설계: `docs/superpowers/specs/2026-08-05-ai-marketing-engine-design.md`
- 원칙: 각 작업은 작은 변경 단위로 수행하고 검증 후 다음 단계로 이동한다.
- 현재 단계에서는 코드 템플릿 대신 파일 책임, 계약, 완료 조건을 정의한다.

## 0. 구현 전 의사결정 게이트

### 0.1 Assessment 권리와 데이터 경계 확정

- 산출물: `docs/decisions/assessment-data-boundary.md`
- 결정: API 여부, 저장 허용 필드, 결과 표시 범위, 부모·컨설턴트 공유 조건, 보존기간
- 검증: Career Direct 계약 담당자와 승인된 문서가 있어야 Phase 3로 진행 가능

### 0.2 개인정보·마케팅 정책 확정

- 산출물: `docs/decisions/privacy-consent-matrix.md`
- 결정: 목적별 동의, 필수·선택 구분, 철회, 보존·삭제, 국외 처리, AI 사용 고지
- 검증: 법률 검토 대상 항목과 제품 요구사항을 분리하고 책임자를 지정

### 0.3 공급자 선택 기록

- 산출물: `docs/decisions/provider-selection.md`
- 결정: Supabase 리전, 이메일 공급자, Cal.com 방식, AI 모델 공급자, 분석 도구
- 검증: 비용, 데이터 위치, SLA, 웹훅, 삭제 지원, 라이선스 비교 완료

## Phase 1. 플랫폼 기반과 계약

### 1.1 모노레포 목표 구조 정의

- 대상 경로: `apps/www`, `apps/admin`, `packages/domain`, `packages/database`, `packages/events`, `packages/integrations`, `packages/analytics`, `packages/ai`, `payload`
- 작업: 각 패키지의 책임, 허용 의존성, 공개 인터페이스 문서화
- 완료 조건: 순환 의존성이 없고 고객 웹·관리자·CMS의 경계가 명확함
- 검증: 아키텍처 의존성 표 리뷰

### 1.2 환경과 비밀정보 정책

- 대상: 루트 및 앱별 환경 계약 문서
- 작업: 공개 환경값, 서버 전용 값, 공급자 키, 키 회전 책임 정의
- 완료 조건: 브라우저에 노출 가능한 값과 불가능한 값이 구분됨
- 검증: 비밀정보 위협 모델 리뷰

### 1.3 도메인 용어집

- 산출물: `docs/domain/glossary.md`
- 작업: person, lead, participant, consultant, organization, journey, registration 등 정의
- 완료 조건: 마케팅 용어와 제품 상태가 충돌하지 않음
- 검증: 제품·마케팅·운영 공동 리뷰

### 1.4 이벤트 명명 및 버전 규칙

- 산출물: `docs/contracts/events.md`
- 작업: 공통 envelope, 버전 정책, idempotency, correlation, 개인정보 등급 정의
- 완료 조건: MVP 이벤트마다 생산자·소비자·재시도 정책이 있음
- 검증: 이벤트 계약 테이블 완성

## Phase 2. 신원·동의·고객 데이터 기반

### 2.1 신원 모델

- 목표 경로: `packages/domain/identity`, `packages/database/migrations`
- 작업: person, contact point, organization, membership, role 경계 구현 계획 확정
- 완료 조건: 익명 리드가 가입 사용자로 안전하게 연결되고 병합 이력이 유지됨
- 검증: 신규 방문자, 기존 리드 가입, 중복 이메일, 기관 소속 시나리오

### 2.2 동의 모델

- 목표 경로: `packages/domain/consent`
- 작업: 목적, 정책 버전, 증거, 철회, 접근 grant 정의
- 완료 조건: 마케팅 발송과 부모·컨설턴트 접근이 명시적 동의로 차단·허용됨
- 검증: 동의, 거부, 철회, 만료, 정책 변경 시나리오

### 2.3 RLS 정책 설계

- 산출물: `docs/security/rls-matrix.md`
- 작업: 역할+관계+grant 기반 테이블별 읽기·쓰기 정책
- 완료 조건: 마케터가 Assessment를 볼 수 없고 부모가 grant 없는 자녀 데이터를 볼 수 없음
- 검증: 허용·거부 테스트 매트릭스

### 2.4 통합 고객 프로필

- 목표 경로: `packages/domain/customer-profile`
- 작업: 선언·행동·거래·AI 추론 사실의 출처와 우선순위 정의
- 완료 조건: AI 추론이 확인된 사실을 덮어쓰지 않음
- 검증: 상충 사실, 만료 사실, 사용자 수정 시나리오

## Phase 3. 이벤트·분석 기반

### 3.1 도메인 이벤트와 Outbox

- 목표 경로: `packages/events`, `packages/database/migrations`
- 작업: 원자적 이벤트 기록, 전달 상태, 재시도, dead-letter 설계
- 완료 조건: 비즈니스 변경과 이벤트가 함께 기록되고 재전송이 중복 결과를 만들지 않음
- 검증: 공급자 장애, 중복 웹훅, 순서 역전, 재처리 시나리오

### 3.2 웹 이벤트 수집

- 목표 경로: `apps/www/src`의 분석 경계, `packages/analytics`
- 작업: 익명 ID, 세션, UTM, 동의 전후 수집 범위 정의
- 완료 조건: 개인정보 동의에 맞게 최소 이벤트가 수집됨
- 검증: 익명→리드→회원 식별 연결 및 opt-out

### 3.3 분석 데이터마트

- 목표 경로: `packages/analytics/models`
- 작업: 일별 콘텐츠, 캠페인, 퍼널, 이메일, 등록 집계 정의
- 완료 조건: 대시보드가 운영 테이블을 직접 무거운 쿼리로 조회하지 않음
- 검증: 샘플 이벤트에서 KPI 수기 계산과 집계 일치

### 3.4 기여도 모델 MVP

- 산출물: `docs/analytics/attribution.md`
- 작업: first-touch, last-touch, 직접 전환, 캠페인 창 정의
- 완료 조건: 복잡한 AI 기여도 없이 해석 가능한 기본 지표 제공
- 검증: 다중 유입 시나리오 예제

## Phase 4. CMS·SEO·리드 확보

### 4.1 Payload 콘텐츠 모델

- 목표 경로: `payload/collections`, `payload/blocks`
- 작업: pages, posts, topics, keywords, briefs, lead magnets, testimonials, knowledge documents 정의
- 완료 조건: 콘텐츠와 고객 PII가 분리되고 초안·검토·승인 상태가 있음
- 검증: 한국어 글 작성, 예약 발행, 이전 버전 복원

### 4.2 공개 웹 콘텐츠 경험

- 목표 경로: `apps/www/src/app`
- 작업: 대상별 랜딩, 블로그, 프로그램, 컨설턴트 모집 정보구조 계획
- 완료 조건: 서버 렌더링, 메타데이터, canonical, 사이트맵, 구조화 데이터 요구가 명시됨
- 검증: 검색 크롤링 체크리스트와 접근성 리뷰

### 4.3 리드 캡처

- 목표 경로: `apps/www/src` 폼 경계, `packages/domain/leads`
- 작업: 리드 마그넷, 상담, 기관 문의, 컨설턴트 관심 폼과 동의 결합
- 완료 조건: 중복 리드를 병합하고 first/latest touch를 보존함
- 검증: 재제출, 잘못된 연락처, 동의 거부, 봇 제출 시나리오

### 4.4 SEO 운영 워크플로

- 목표 경로: `packages/ai/seo`, Payload 승인 흐름
- 작업: 키워드→브리프→초안→검토→발행→갱신 상태 설계
- 완료 조건: AI가 검증되지 않은 검색량을 생성하지 않고 무승인 본문이 발행되지 않음
- 검증: 근거 없음, 중복 주제, 키워드 잠식 시나리오

## Phase 5. 캠페인·이메일·고객 여정

### 5.1 세그먼트 엔진

- 목표 경로: `packages/domain/segments`
- 작업: 규칙 버전, 가입·이탈 이유, 민감 로직 차단 정의
- 완료 조건: 동일 이벤트 재처리에도 membership 이력이 안정적임
- 검증: 대학생, 직장인, 부모, 기관, 컨설턴트 후보 규칙

### 5.2 리드 점수 엔진

- 목표 경로: `packages/domain/scoring`
- 작업: engagement, intent, fit 분리, 설명 가능한 가중치, 감쇠 정책
- 완료 조건: 점수와 이유가 함께 저장되고 민감 특성이 입력에서 제외됨
- 검증: 행동 시계열별 예상 점수 비교

### 5.3 고객 여정 엔진

- 목표 경로: `packages/domain/journeys`
- 작업: 진입, 대기, 조건, 발송, 목표, 종료, 빈도 제한 정의
- 완료 조건: 한 사람이 같은 버전의 여정에 중복 등록되지 않음
- 검증: 전환, 수신거부, 조건 변경, 실패 재시도

### 5.4 이메일 공급자 연동

- 목표 경로: `packages/integrations/email`
- 작업: 구독자 동기화, 발송, 웹훅, suppression, bounce 계약
- 완료 조건: 수신거부가 모든 마케팅 발송보다 우선함
- 검증: 중복 웹훅, hard/soft bounce, 공급자 장애

### 5.5 초기 육성 여정

- 대상: 대학생, 직장인, 부모, 컨설턴트 후보
- 작업: 각 여정의 진입 이벤트, 3~5개 메시지, 목표, 종료 조건 승인
- 완료 조건: 콘텐츠·CTA·발송 빈도가 검토됨
- 검증: 메시지 미리보기와 여정 시뮬레이션

## Phase 6. 예약·워크숍·CRM 운영

### 6.1 Cal.com 연동

- 목표 경로: `packages/integrations/calendar`
- 작업: 예약 생성·변경·취소·참석 웹훅 계약
- 완료 조건: 외부 ID와 내부 appointment가 1:1로 연결됨
- 검증: 중복, 취소 후 재예약, 노쇼

### 6.2 워크숍 등록

- 목표 경로: `packages/domain/programs`, `apps/www` 등록 흐름
- 작업: 개설, 정원, 등록, 결제 상태, 대기자, 출석, 수료 정의
- 완료 조건: 정원 초과와 취소가 대기자 초대로 안전하게 연결됨
- 검증: 동시 마지막 좌석, 결제 실패, 대기자 거절

### 6.3 운영 CRM

- 목표 경로: `packages/domain/crm`, `apps/admin/src`
- 작업: 개인·기관·컨설턴트 파이프라인, 단계 이력, 업무, SLA 화면
- 완료 조건: 단계 변경이 이벤트와 이력으로 남고 민감 데이터가 표시되지 않음
- 검증: 자동·수동 단계 변경 충돌, 담당자 변경, 기한 초과

### 6.4 컨설턴트 모집

- 목표 경로: `packages/domain/consultants`, `apps/www`, `apps/admin`
- 작업: 관심→설명회→지원→검토→인터뷰→교육→승인 흐름
- 완료 조건: AI 요약과 사람의 최종 결정이 분리됨
- 검증: 미완료 지원, 중복 지원, 자격 만료

## Phase 7. AI 챗봇과 콘텐츠 AI

### 7.1 AI 모델 게이트웨이

- 목표 경로: `packages/ai/gateway`
- 작업: 사용사례별 모델, 비용, timeout, fallback, 데이터 등급 제한
- 완료 조건: 앱이 공급자 SDK에 직접 의존하지 않음
- 검증: 공급자 장애, 비용 한도, 허용되지 않은 입력 등급

### 7.2 지식 수집과 검색

- 목표 경로: `packages/ai/knowledge`
- 작업: 승인된 Payload 문서만 버전·청크·임베딩 처리
- 완료 조건: 폐기 문서가 검색되지 않고 답변이 문서 버전을 인용함
- 검증: 삭제, 갱신, 권한 제한, 무근거 질문

### 7.3 공개 AI 챗봇

- 목표 경로: `apps/www` 챗봇 경계, `packages/ai/chatbot`
- 작업: 의도, 안전 분류, RAG, 도구 확인, 사람 연결 흐름
- 완료 조건: Assessment 생성·민감 데이터 공개·무확인 행동이 불가능함
- 검증: 정상 FAQ, 악의적 프롬프트, 부모의 자녀정보 요청, 위기 표현

### 7.4 콘텐츠 생성 보조

- 목표 경로: `packages/ai/content`, Payload 검토 화면
- 작업: 브리프, 초안, 메타데이터, 근거, 승인 기록
- 완료 조건: AI 초안은 게시 상태로 직접 전환할 수 없음
- 검증: 출처 없는 수치, 금지된 보장 표현, 중복 콘텐츠

### 7.5 AI 평가 체계

- 산출물: `docs/ai/evaluation-suite.md`
- 작업: 한국어 FAQ, 브랜드, 안전, 근거, 상담 전환 테스트셋 정의
- 완료 조건: 모델 또는 프롬프트 변경 전 기준 점수를 통과함
- 검증: 고정 평가셋과 사람 샘플 리뷰

## Phase 8. 최적화와 대시보드

### 8.1 관리자 대시보드

- 목표 경로: `apps/admin/src`
- 화면: 경영, 퍼널, SEO, 이메일, 워크숍, 컨설턴트, 자동화, AI 품질
- 완료 조건: 지표 정의와 시간대·필터가 일관됨
- 검증: 집계 원본 대조와 빈 상태·오류 상태

### 8.2 랜딩페이지 실험

- 목표 경로: `packages/domain/experiments`, Payload variants
- 작업: 가설, 배정, 주 지표, guardrail, 중단 기준
- 완료 조건: 실험 간 중복 충돌과 무근거 자동 승자 선정을 방지함
- 검증: 안정적 배정, 봇 제외, 샘플 부족

### 8.3 다음 최적 행동

- 목표 경로: `packages/domain/recommendations`
- 작업: 먼저 설명 가능한 규칙 기반으로 평가·워크숍·상담 CTA 추천
- 완료 조건: 추천 이유와 suppression 사유가 표시됨
- 검증: 동의 없음, 이미 구매, 최근 노쇼, 기관 참가자

### 8.4 Twenty 도입 평가

- 산출물: `docs/decisions/twenty-adoption-review.md`
- 조건: CRM 사용자 수, 파이프라인 복잡도, 수작업량이 사전 기준을 초과할 때만 검토
- 완료 조건: 데이터 중복·라이선스·운영 비용 대비 이점 확인
- 검증: native CRM 유지안과 비교

## 릴리스 게이트

### 내부 알파

- 신원·동의·리드·이벤트·Payload 기본 기능
- 실제 고객 데이터 없이 합성 데이터만 사용
- 보안·RLS 테스트 통과

### 제한 베타

- 하나의 개인 고객 여정, 하나의 워크숍, 하나의 컨설턴트 모집 여정
- 이메일 suppression, 예약, 관리자 CRM 사용 가능
- AI는 내부 콘텐츠 보조만 허용

### 공개 MVP

- 공개 챗봇은 승인된 FAQ/RAG 범위만 지원
- Assessment·워크숍·코칭 퍼널 분석 가능
- 자동화 실패 대시보드와 수동 복구 절차 준비
- 개인정보·운영·AI 사고 대응 절차 승인

## 전체 검증 전략

- 도메인 규칙: 상태 전이와 불변조건 테스트
- 데이터 권한: 역할·관계·grant별 허용/거부 테스트
- 통합: 계약 테스트, 서명 검증, 중복 웹훅 테스트
- 고객 여정: 시뮬레이션과 시간 이동 테스트
- 분석: 이벤트 원본과 집계 수치 대조
- AI: 고정 평가셋, 근거성, 안전, 한국어 품질, 비용 한도
- 복구: 공급자 장애, dead-letter 재처리, 키 회전, 데이터 삭제 훈련
- 사용자 승인: 참여자, 컨설턴트, 마케터, 운영자별 수용 테스트

## 권장 구현 순서

`의사결정 게이트 → 기반 계약 → 신원·동의 → 이벤트·분석 → CMS·리드 → 세그먼트·이메일 → 예약·워크숍·CRM → AI → 최적화`

AI를 앞당기지 않는다. 동의, 고객 원본, 이벤트, 승인 워크플로가 먼저 준비되어야 AI가 안전하고 측정 가능하게 동작한다.
