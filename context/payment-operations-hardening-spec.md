# 결제 운영 안정화 확정 명세

상세 설계: `docs/superpowers/specs/2026-08-10-payment-operations-hardening-design.md`

## 고정 결정

- 콜백 신청에 `is_test`를 저장하며 기본값은 `false`다.
- 테스트 건은 관리자 화면에서 유지하되 결제·매출·환불 통계에서 제외한다.
- 금전·서비스 상태 변경은 추가 전용 운영 이력에 남긴다.
- 상태 변경과 운영 이력 insert는 같은 DB 트랜잭션에서 성공하거나 함께 실패한다.
- 고객 본부 등록은 고객이 평가 이메일 링크를 통해 본부 시스템에 직접 등록한 사실이다.
- 고객 본부 등록은 평가 크레딧 사용 개시 시점이며 이후 165,000원은 환불 대상에서 제외된다.
- 단순 링크 클릭과 고객 본부 등록을 구분한다.
- 환불은 미리보기 → 접수 → 실제 수동 이체 확인 → 완료 순서로 처리한다.
- 자동 취소·독촉·재시도·입금조회·환불이체는 이번 범위에 포함하지 않는다.

## 성공 조건

1. 테스트 데이터가 실제 고객 통계를 왜곡하지 않는다.
2. 입금·증빙·평가·컨설팅·환불 변경 이력을 관리자 상세에서 확인한다.
3. 위험 작업 전에 의미와 금액을 다시 확인한다.
4. 고객 본부 등록의 의미와 165,000원 환불 제한이 명확하다.
5. 예외 필터가 실제 DB 상태와 일치한다.
6. 중복 클릭에도 상태와 이력이 한 번만 저장된다.
