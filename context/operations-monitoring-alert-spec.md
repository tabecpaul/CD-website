# 운영 장애 모니터링 및 알림 명세

상세 설계의 정본은 `docs/superpowers/specs/2026-08-10-operations-monitoring-alert-design.md`다.

## 제품 결정

- 매일 오전 9시(한국시간) 점검한다.
- 실제 운영 문제가 1건 이상일 때만 관리자 이메일을 발송한다.
- 테스트 콜백과 연결 결제는 모든 집계에서 제외한다.
- 동일 날짜의 동일 문제 구성은 한 번만 발송한다.
- 고객 식별정보는 요약 이메일과 실행 기록에 저장하지 않는다.
- 자동 상태 변경·자동 취소·자동 환불은 하지 않는다.

## 감지 항목

- 입금기한 초과
- 결제·환불 이메일 실패
- 콜백·일정 이메일 실패
- 증빙 처리 대기
- 환불 처리 대기
- 리드 이메일 작업 30분 이상 지연
- 콜백 알림 작업 30분 이상 지연
- 주요 Cron 성공 기록 지연 또는 없음

## 실행 계약

- 엔드포인트: `GET /api/cron/operations-monitor`
- 인증: `Authorization: Bearer ${CRON_SECRET}`
- 성공 및 문제 없음: 200, 이메일 없음
- 성공 및 문제 있음: 200, 중복이 아니면 이메일 한 통
- 인증 실패: 401
- 설정 누락: 503
- 내부 오류: 500 또는 503, 안전한 오류 코드만 로그

## 저장 계약

- `system_job_runs`: 주요 작업의 시작·성공·실패 기록
- `operations_alert_deliveries`: 한국 날짜와 fingerprint별 발송 상태
- 두 테이블 모두 RLS 활성화, 공개 정책 없음
- 발송 실패와 15분 이상 멈춘 발송은 다음 실행에서 재시도 가능

## 관리자 화면

- 마지막 점검 성공 시각
- 현재 이상 총건수
- 항목별 운영 필터 링크
- 모니터링 미실행 또는 실패 경고
