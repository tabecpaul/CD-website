# 콘텐츠 게시 운영 가이드

## 매일 확인할 곳

관리자 로그인 후 `/admin/content`를 엽니다. 개별 캠페인 폴더를 찾아다니지 않아도 오늘 발행, 이번 주 예정, 확인 지연과 발행 완료 상태를 확인할 수 있습니다.

## 전날 준비

1. 오전 9시 준비 이메일에서 해당 콘텐츠의 관리자 상세 화면을 엽니다.
2. 네이버·인스타그램·페이스북·Threads 문안을 확인합니다.
3. 카드뉴스 문안과 대체 텍스트, UTM 링크를 확인합니다.
4. 실제 카드 이미지가 준비되었는지 별도로 확인합니다.
5. 준비된 채널을 `준비 완료`로 저장합니다.

## 발행 당일

1. 각 발행 시각 30분 전 이메일을 확인합니다.
2. 관리자 상세 화면의 복사 버튼으로 문안과 UTM 링크를 복사합니다.
3. 외부 채널에 직접 게시합니다.
4. 공개된 게시물 URL을 관리자 화면에 입력합니다.
5. `게시 URL 저장·발행 완료`를 누릅니다.

인스타그램과 페이스북은 같은 시각에 한 통의 알림으로 안내됩니다. 시스템은 게시를 대신 수행하지 않으며 URL을 입력하기 전에는 발행 완료로 판단하지 않습니다.

## 다음 날 성과 확인

1. 오전 9시 성과 확인 이메일에서 관리자 상세 화면을 엽니다.
2. 각 채널의 조회·좋아요·댓글·저장·공유·링크 클릭을 확인합니다.
3. 제공되지 않는 지표는 비워 둡니다.
4. 값을 입력하고 `성과 확인 완료`를 누릅니다.

고객 개인정보, 상담 내용, 건강·가족·종교 관련 민감정보는 운영 메모에 기록하지 않습니다.

## 알림 문제 대응

- 이메일을 받지 못하면 `/admin/content`의 일정과 상태를 먼저 확인합니다.
- `/admin/callbacks`의 운영 모니터에서 `콘텐츠 알림 이메일 실패` 또는 `콘텐츠 알림 Cron 이상`을 확인합니다.
- 환경 변수 `CONTENT_NOTIFICATION_EMAIL`, `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `CRON_SECRET`을 점검합니다.
- 발송 실패는 최대 3회까지 재시도되며 동일한 성공 알림은 중복 발송되지 않습니다.
- 이메일 장애가 발생해도 문안, 일정, 게시 URL과 성과 데이터는 보존됩니다.

## 배포 시 설치 순서

1. 검증 환경에서 `packages/db/drizzle/0013_small_puma.sql`을 적용합니다.
2. 운영 환경에 `CONTENT_NOTIFICATION_EMAIL=tabecpaul@gmail.com`을 설정합니다.
3. 사이트를 배포하고 관리자 로그인과 `/admin/content`를 확인합니다.
4. `packages/db/operations/schedule-content-reminder-cron.sql`을 실행합니다.
5. Cron HTTP 응답과 `system_job_runs`의 `content-reminders` 성공 기록을 확인합니다.

프로덕션 마이그레이션과 Cron 등록은 코드 검증 후 승인받아 수행합니다.

## 2~3개월 후 자동 게시 검토

발행 일정 준수율, 누락률, 게시물당 운영 시간, 게시 직전 수정 빈도와 UTM 전환을 검토합니다. 반복성이 충분하고 플랫폼별 수정이 적을 때만 네이버·Meta·Threads 자동 게시를 별도 설계합니다.
