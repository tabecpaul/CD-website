# Career Direct Korea 전환 분석 대시보드 설계

## 1. 목적

청년 직장인 진로방향 자가진단 퍼널의 방문부터 상담 신청까지를 자사 데이터로 측정한다. 개인별 행동을 열람하는 CRM이 아니라 기간·유입경로별 집계 지표를 제공하는 1인용 내부 대시보드를 만든다.

측정 퍼널은 다음과 같다.

1. 랜딩페이지 방문
2. PDF 신청
3. 이메일 전달
4. PDF 다운로드
5. Career Direct 평가 CTA 클릭
6. 상담 신청

## 2. 범위

### 포함

- 기존 공개 웹사이트의 `/admin/analytics` 내부 대시보드
- `/admin/login` 1인용 관리자 로그인
- 최근 7일·30일·90일 기간 필터
- 퍼널 단계별 건수와 직전 단계 대비 전환율
- 이메일 발송·전달·반송·불만·수신 거부 지표
- `utm_source`, `utm_medium`, `utm_campaign`별 성과표
- 익명 방문 ID 기반 자사 이벤트 수집
- 13개월 이벤트 보존과 자동 삭제 기반

### 제외

- 개인별 방문 타임라인
- 이메일·이름·전화번호를 보여주는 CRM 화면
- Google Analytics, Meta Pixel 등 외부 행동 추적 도구
- 여러 관리자 계정, 역할, 비밀번호 재설정
- 실시간 스트리밍 대시보드
- PDF 답변 또는 Career Direct 평가 결과 수집

## 3. 선택한 접근 방식

대시보드는 별도 `apps/admin` 배포가 아니라 기존 `apps/www` 안에 둔다. 현재는 관리자 한 명과 단일 퍼널이므로 Vercel 프로젝트, 도메인, 환경변수, 배포를 추가하지 않는 편이 운영상 단순하다. CRM과 복수 관리자가 필요해질 때 전용 관리자 앱으로 이전한다.

Supabase PostgreSQL을 행동 이벤트와 기존 리드·이메일 상태의 집계 원본으로 사용한다. 외부 분석 도구를 사용하지 않아 국외 데이터 처리와 쿠키 동의 범위를 불필요하게 늘리지 않는다.

## 4. 이벤트 모델

새 `analytics_events` 테이블은 다음 정보를 저장한다.

- 서버 생성 기본키
- 클라이언트 또는 서버가 생성한 고유 이벤트 ID
- 익명 방문 ID(없을 수 있음)
- 이벤트 이름
- 발생 시각
- 페이지 경로
- CTA 위치
- `utm_source`, `utm_medium`, `utm_campaign`
- 저장 시각

허용 이벤트 이름은 다음 다섯 개로 제한한다.

- `landing_viewed`
- `lead_submitted`
- `pdf_downloaded`
- `assessment_cta_clicked`
- `consultation_submitted`

`email_delivered`와 발송·반송·불만은 새 이벤트로 복제하지 않고 기존 `lead_magnet_email_jobs` 및 `lead_magnet_email_events`에서 집계한다. 수신 거부는 기존 `lead_magnet_leads.marketing_unsubscribed_at`에서 집계한다.

이벤트 고유 ID에는 unique constraint를 둬 브라우저 재시도와 네트워크 재전송을 멱등 처리한다. 이벤트 이름, 경로, CTA 위치, UTM은 서버 허용 목록과 길이 제한을 적용한다.

## 5. 익명 방문 식별

브라우저에는 서버가 생성한 암호학적으로 무작위인 방문 ID를 first-party 쿠키로 저장한다. 공개 이벤트 API가 쿠키를 읽어 이벤트에 연결하므로 클라이언트 JavaScript는 방문 ID 값을 직접 읽지 않는다.

- 쿠키 이름: `cdk_vid`
- 만료: 30일
- 속성: `HttpOnly`, `Secure`, `SameSite=Lax`, path `/`
- 이름·이메일·전화번호·IP·User-Agent 원문을 ID 생성에 사용하지 않음

방문 ID는 한 사람을 현실의 신원으로 식별하지 않는다. 쿠키 삭제, 다른 브라우저 또는 다른 기기는 새 방문자로 계산한다. 기간 내 방문자 수는 `landing_viewed`의 고유 방문 ID 수로 계산해 새로고침으로 수치가 과도하게 늘지 않게 한다.

이메일에서 PDF를 다운로드할 때 브라우저 쿠키가 없을 수 있다. 이 경우 방문 ID 없이 다운로드 이벤트를 저장하고, 다운로드 토큰 자체는 분석 테이블에 저장하지 않는다. 유입 성과는 토큰으로 조회한 리드의 UTM 값을 이벤트에 복사해 집계한다. 리드 ID나 이메일은 분석 이벤트에 저장하지 않는다.

## 6. 이벤트 데이터 흐름

### 랜딩페이지 방문

클라이언트가 `/career-check` 로딩 후 UTM과 고유 이벤트 ID로 `landing_viewed`를 전송한다. 서버는 방문 쿠키가 없으면 생성하고 같은 이벤트 ID 재전송은 한 번만 저장한다.

### PDF 신청

리드 저장과 발송 일정 생성이 성공한 후 서버가 `lead_submitted`를 기록한다. 분석 기록 실패는 신청 성공을 되돌리지 않으며 오류 로그만 남긴다.

### PDF 다운로드

다운로드 토큰 검증과 파일 응답 준비가 성공하면 서버가 `pdf_downloaded`를 기록한다. 토큰, 이메일, 리드 ID는 분석 이벤트에 넣지 않는다.

### 평가 CTA 클릭

랜딩페이지의 Career Direct 공식 출처 링크와 온라인 평가 링크를 추적 가능한 CTA 컴포넌트로 감싼다. `sendBeacon` 또는 `fetch(..., { keepalive: true })`로 이벤트를 전송하고 외부 링크 이동은 기다리지 않는다. `cta_location`으로 CTA 위치를 구분한다.

### 상담 신청

상담 신청 DB 저장이 성공한 후 서버가 `consultation_submitted`를 기록한다. 상담 신청의 이름·이메일·전화번호는 분석 이벤트로 복제하지 않는다.

## 7. 대시보드

경로는 `/admin/analytics`이며 다음 네 영역을 제공한다.

### 기간 선택

- 최근 7일
- 최근 30일(기본값)
- 최근 90일

모든 기간은 한국 표준시 기준 날짜 경계를 사용한다.

### 핵심 퍼널

- 고유 방문자
- PDF 신청
- PDF 다운로드
- 평가 CTA 클릭
- 상담 신청

각 카드에는 기간 내 건수와 직전 단계 대비 전환율을 표시한다. 이메일 전달은 신청과 다운로드 사이의 운영 상태로 별도 표시하며 사용자 행동 퍼널의 분모를 왜곡하지 않는다.

### 이메일 상태

- 발송
- 전달
- 반송
- 불만
- 수신 거부

반송률과 불만률은 해당 기간 발송 건수를 분모로 사용한다.

### 유입 성과

`utm_source`, `utm_medium`, `utm_campaign` 조합별로 방문자·신청·다운로드·CTA·상담 건수와 전환율을 보여준다. 값이 없는 유입은 `(direct)`로 묶는다. 원시 이메일 주소나 개인별 이벤트 목록은 제공하지 않는다.

## 8. 관리자 인증과 보안

`/admin/login`에서 1인용 비밀번호를 받는다.

- `ADMIN_DASHBOARD_PASSWORD_HASH`: Node.js `scrypt`로 만든 비밀번호의 서버 전용 salt·hash 문자열
- `ADMIN_DASHBOARD_SESSION_SECRET`: 세션 서명 비밀값
- 로그인 성공 시 `ADMIN_DASHBOARD_SESSION_SECRET`을 사용한 HMAC-SHA256 서명으로 8시간 유효 세션 쿠키 발급
- 세션 쿠키: `HttpOnly`, `Secure`, `SameSite=Strict`
- 모든 관리자 페이지와 집계 API에서 서명·만료 재검증
- 관리자 경로에 `noindex`, `nofollow`
- 로그인 실패는 IP를 세션 비밀값으로 해시한 메모리 키에 짧은 요청 제한을 적용하되 IP 원문과 해시를 DB나 로그에 저장하지 않음
- 인증 오류 응답은 비밀번호 존재 여부나 설정값을 노출하지 않음

서버리스 인스턴스별 메모리 제한은 완전한 분산 공격 방어가 아니므로, 운영 규모가 커지면 Vercel 방화벽 또는 외부 rate limit 저장소로 교체한다. MVP에서는 강한 관리자 비밀번호와 비공개 경로, 요청 제한을 함께 사용한다.

공개 이벤트 API는 허용된 `Origin`, 작은 요청 본문 크기, 이벤트별 필드 allowlist, 길이 제한을 검증한다. 방문 쿠키는 서버만 생성하고 읽는다. 자동화된 이벤트 남용을 완전히 막을 수는 없으므로 비정상 급증은 대시보드에서 운영 신호로 보고, 필요할 때 Vercel 방화벽 제한을 추가한다.

## 9. 집계 경계

- 방문자는 고유 방문 ID 수다.
- 신청·다운로드·CTA·상담은 이벤트 건수다.
- 동일 사용자의 재신청은 새로운 전환 행동으로 집계한다.
- 쿠키가 없는 다운로드도 전체 다운로드 수에는 포함되지만 고유 방문자 기반 개인 여정으로 연결하지 않는다.
- 이 대시보드는 집계 퍼널이며 사용자 단위 multi-touch attribution을 제공하지 않는다.
- 이벤트 처리 지연이나 차단으로 수치가 결제·회계 원장처럼 완전하다고 가정하지 않는다.

## 10. 오류 처리

- 분석 이벤트 저장 실패는 PDF 신청·다운로드·CTA 이동·상담 신청을 차단하지 않는다.
- 유효하지 않은 이벤트 이름, 과도한 길이, 허용되지 않은 필드는 `400`으로 거부한다.
- 중복 이벤트 ID는 성공으로 응답하되 새 행을 만들지 않는다.
- 인증되지 않은 관리자 요청은 로그인으로 이동하거나 `401`을 반환한다.
- 집계 쿼리 실패 시 개인 데이터나 SQL 오류를 노출하지 않는 오류 화면을 표시한다.
- 환경변수 누락 시 관리자 로그인은 닫힌 상태로 실패한다.

## 11. 보존과 고지

- 익명 이벤트 원본: 13개월
- 방문 ID 쿠키: 30일
- 13개월이 지난 이벤트는 Supabase Cron의 일일 정리 작업으로 삭제
- 집계 대시보드는 보존기간 안의 원본만 사용

개인정보처리방침에 자사 전환 분석 목적, 익명 방문 ID, UTM, 이벤트 종류, 30일 쿠키와 13개월 원본 보존을 공개한다. 행동 기반 광고나 외부 광고 프로파일링에는 사용하지 않는다.

## 12. 검증

### 입력·이벤트

- 허용되지 않은 이벤트 이름 거부
- 이메일·전화번호 형태의 분석 속성 거부
- 최대 길이를 넘는 경로·UTM 거부
- 같은 이벤트 ID를 두 번 보내도 한 행만 저장

### 퍼널

- 랜딩 방문, 신청, 다운로드, 각 CTA 위치, 상담 신청 기록
- 신청·다운로드·상담의 분석 실패가 사용자 성공 응답을 바꾸지 않음
- UTM이 신청과 다운로드 집계에 유지됨

### 인증

- 올바른 비밀번호 로그인
- 잘못된 비밀번호 거부
- 쿠키 위변조와 8시간 만료 거부
- 비로그인 관리자 페이지·API 차단
- 관리자 페이지 검색 색인 차단

### 집계

- 7·30·90일 한국 표준시 경계
- 기간 내 고유 방문자 계산
- 단계별 전환율과 0 분모 처리
- UTM 없는 유입의 `(direct)` 묶음
- 기존 이메일 작업 상태와 이벤트의 집계 정확성

## 13. 완료 기준

- 공개 퍼널의 다섯 행동 이벤트가 개인정보 없이 저장된다.
- 이메일 전달·반송·불만·수신 거부가 기존 원장에서 집계된다.
- 1인용 관리자만 `/admin/analytics`를 열 수 있다.
- 7·30·90일 퍼널과 UTM 표가 정확히 표시된다.
- 분석 장애가 공개 사용자의 신청·다운로드·이동·상담을 막지 않는다.
- 개인정보처리방침과 보존 정책이 구현과 일치한다.
