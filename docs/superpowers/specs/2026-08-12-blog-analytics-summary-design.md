# 블로그 운영 분석 요약 설계

## 목적

1인 운영자가 `/admin/analytics` 한 화면에서 블로그의 도달, 독자, 다음 행동과 채널별 유입을 빠르게 판단할 수 있게 한다.

## 범위

- 블로그 요약 카드: 글 조회, 고유 독자, 자가진단 클릭, 콜백 클릭
- 기존 글별 성과 표 유지
- UTM 유입 표에서 블로그 직접 유입 방문을 포함
- 연결된 테스트 데이터 제외 규칙 유지
- 개인정보는 수집하거나 표시하지 않음

## 집계 정의

- 글 조회: `blog_article_viewed` 이벤트 수
- 고유 독자: 해당 이벤트의 고유 `anonymous_id` 수
- 자가진단 클릭: 블로그 경로에서 발생한 `official_site_clicked` 수
- 콜백 클릭: 블로그 경로에서 발생한 `callback_cta_clicked` 수
- 채널 방문: UTM 조합별 `landing_viewed`, `official_page_viewed`, `blog_article_viewed`의 고유 방문자 합집합

각 방문자는 같은 UTM 조합 안에서 한 번만 계산한다. 기존 신청·다운로드·콜백 집계 정의는 바꾸지 않는다.

## 화면 구성

기존 `블로그 성과` 제목 아래에 네 개의 요약 카드를 배치한다. 그 아래에 현재 글별 성과 표를 그대로 둔다. UTM 표의 `방문`은 공식 사이트 및 블로그 직접 유입까지 포함하는 의미로 확장한다.

## 확장성

원천 이벤트 스키마는 변경하지 않는다. 향후 다음 기능은 동일 데이터를 날짜·경로·UTM 차원으로 다시 집계해 추가할 수 있다.

- 날짜별 조회·전환 추이 차트
- 글별 상세 분석 화면
- 채널·캠페인·소재 비교
- 콘텐츠 보조 전환과 최종 결제 기여 분석

## 오류 및 성능

현재 대시보드의 병렬 SQL 집계 패턴을 유지한다. 신규 요약은 기존 블로그 집계 결과에서 합산하여 추가 쿼리를 만들지 않는다. 기간은 기존과 동일하게 7·30·90일만 지원한다.

## 검증

- 0건 기간에서 모든 카드가 0으로 표시되는지 확인
- 블로그 조회와 CTA 이벤트가 글별 표와 요약 카드에 일치하는지 확인
- 블로그 직행 UTM 방문이 유입 표에 포함되는지 확인
- 테스트 고객과 연결된 익명 이벤트가 제외되는지 확인
- ESLint, TypeScript, 프로덕션 빌드 검증
