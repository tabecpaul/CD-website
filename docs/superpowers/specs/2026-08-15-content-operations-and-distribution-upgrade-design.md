# 콘텐츠 배포 고도화 및 관리자 운영·알림 시스템 설계

## 1. 목적

기존 일반 블로그 6편의 배포 자료를 「신앙과 소명」 3편과 같은 수준으로 고도화하고, 관리자가 파일과 운영표를 일일이 찾지 않아도 모든 콘텐츠의 발행 준비·게시·성과 확인을 한곳에서 관리하도록 한다.

첫 2~3개월은 관리자 운영판과 이메일 알림을 사용하되 실제 외부 채널 게시는 관리자가 직접 수행한다. 이 기간의 운영 데이터를 검토한 뒤 네이버·Meta·Threads 자동 게시 연동 여부를 별도 결정한다.

## 2. 작업 범위

### 2.1 기존 6편 배포 자료 고도화

대상 콘텐츠:

1. 진로 불안과 번아웃
2. 네 가지 진로 나침반
3. 이직 또는 잔류 결정
4. AI 일자리 불안
5. 좋아하는 일과 잘하는 일
6. 경력 전환 현실 조건

각 콘텐츠에 다음 자료를 갖춘다.

- 네이버 블로그용 재구성 원고
- 인스타그램·페이스북 카드뉴스 8장 문안
- 인스타그램·페이스북 공용 캡션
- 카드뉴스 접근성용 대체 텍스트
- Threads 연결 글 4~5개
- 공식 원문과 단일 CTA용 UTM 링크
- 발행 일정표와 게시 전후 체크리스트
- 전체 다운로드용 ZIP

기존 네이버 원고·캡션·Threads·UTM 자료는 활용하되, 내용이 현재 공식 원문과 CTA에 맞는지 다시 검수한다. 기존 사용자 파일과 신앙과 소명 캠페인 자료는 변경하지 않는다.

### 2.2 관리자 콘텐츠 운영판

경로는 `/admin/content`로 한다. 기존 관리자 인증과 레이아웃을 재사용한다.

운영판 상단에는 다음 요약을 표시한다.

- 오늘 발행 예정
- 이번 주 발행 예정
- 확인 지연
- 발행 완료

목록에서는 카테고리, 콘텐츠 제목, 발행일과 네이버·인스타그램·페이스북·Threads의 상태를 한눈에 확인한다. 날짜 아래에 시간을 표시하고, 화면 폭이 좁을 때도 상태가 잘리지 않도록 반응형으로 구성한다.

상세 화면에서는 다음 기능을 제공한다.

- 채널별 문안과 카드뉴스 장별 문안 열람
- 문안과 UTM 링크 복사
- 접근성 대체 텍스트 열람 및 복사
- 예정 날짜와 시각 확인
- 실제 게시 URL 입력
- 준비 완료, 발행 완료, 성과 확인 완료 상태 전환
- 조회·좋아요·댓글·저장·공유·링크 클릭 기록
- 운영 메모 기록

콘텐츠 운영 정보만 저장하며 실제 고객 정보나 상담 관련 민감정보는 기록하지 않는다.

## 3. 운영 상태

채널별 상태는 다음 흐름을 사용한다.

1. `draft`: 문안 준비 중
2. `ready`: 게시 준비 완료
3. `due`: 발행 시각 도래
4. `published`: 실제 게시 URL 확인 완료
5. `performance_checked`: 초기 성과 확인 완료

`due`는 예정 시각과 현재 시각을 바탕으로 시스템이 계산해 표시한다. 관리자가 게시 URL을 입력해야 `published`로 바꿀 수 있다. 시스템은 외부 게시 성공 여부를 추측하거나 자동 완료하지 않는다.

예정 시각이 지났는데 `published`가 아니면 `확인 지연`으로 강조한다. 테스트 항목은 별도 표시하고 실제 성과 집계에서 제외한다.

## 4. 데이터 구조

### 4.1 콘텐츠 마스터

- 제목과 slug
- 카테고리
- 공식 원문 URL
- 캠페인 식별자
- CTA 종류와 목적지
- 테스트 여부

### 4.2 채널 작업

- 콘텐츠 마스터 참조
- 채널: naver_blog, instagram, facebook, threads
- 예정 발행 시각
- 상태
- 게시 문안
- 카드뉴스 문안과 대체 텍스트
- UTM URL
- 실제 게시 URL
- 게시 완료 시각
- 운영 메모

### 4.3 알림 이력

- 채널 작업 참조
- 알림 종류
- 예정 시각
- 발송 상태와 발송 시각
- 이메일 서비스 식별자와 실패 코드
- 중복 방지 키

### 4.4 성과 기록

- 채널 작업 참조
- 확인 시각
- 조회수
- 좋아요
- 댓글
- 저장
- 공유
- 링크 클릭
- 운영 메모

숫자 지표는 음수를 허용하지 않는다. 채널에서 제공하지 않는 지표는 비워 둘 수 있다.

## 5. 초기 데이터

현재 공식 블로그 9편과 승인된 캠페인 일정을 초기 등록한다.

- 일반 진로 콘텐츠 6편: 2026년 8월 17·19·21·24·26·28일
- 신앙과 소명 3편: 2026년 8월 18·23·27일
- 네이버 블로그: 08:00 KST
- 인스타그램·페이스북: 19:00 KST
- Threads: 21:00 KST

문안과 링크는 두 캠페인 폴더의 검수된 파일에서 초기화한다. 초기화는 반복 실행해도 중복 레코드를 만들지 않아야 한다.

## 6. 이메일 알림

수신자는 `tabecpaul@gmail.com`이며, 운영 환경 변수로 재정의할 수 있도록 한다.

알림 시점:

- 발행 전날 09:00 KST: 다음 날 전체 준비 안내
- 발행 당일 채널별 예정 시각 30분 전: 게시 실행 안내
- 발행 다음 날 09:00 KST: 게시 URL과 초기 성과 확인 안내

이메일에는 콘텐츠 제목, 채널, 예정 시각, 관리자 상세 화면 링크와 수행할 행동을 포함한다. 긴 전체 원고를 이메일에 넣지 않고 관리자 화면에서 확인하도록 한다.

각 알림에는 채널 작업·알림 종류·기준 날짜를 조합한 중복 방지 키를 사용한다. 같은 알림의 재실행은 새 이메일을 만들지 않는다. 발송 실패 시 데이터는 보존하고 운영판에 경고를 표시하며, 기존 운영 모니터의 확인 필요 항목에 포함한다.

## 7. 자동화 작업

정기 작업은 알림 대상 탐색, 이메일 발송, 결과 기록만 수행한다. 외부 SNS 게시 API는 호출하지 않는다.

- 작업은 일정 범위 안의 발행 전날·당일·다음 날 항목을 조회한다.
- 모든 시각 계산은 Asia/Seoul 기준으로 수행하고 DB에는 표준시로 저장한다.
- 일부 이메일이 실패해도 다른 대상 처리를 계속한다.
- 실행 결과와 마지막 성공 시각을 기존 작업 실행 기록에 남긴다.
- 반복 호출과 동시 실행에서도 중복 알림이 발생하지 않아야 한다.

## 8. 관리자 운영 흐름

1. 전날 이메일을 받고 운영판에서 다음 날 문안·카드뉴스 문안·대체 텍스트·링크를 확인한다.
2. 준비가 끝난 채널을 `ready`로 표시한다.
3. 당일 30분 전 이메일을 받고 문안과 UTM 링크를 복사한다.
4. 외부 채널에 직접 게시한다.
5. 실제 게시 URL을 입력하고 `published`로 완료한다.
6. 다음 날 알림을 받고 초기 성과를 입력한다.
7. 입력 후 `performance_checked`로 완료한다.

관리자는 개별 파일 경로를 기억하거나 운영표를 따로 찾을 필요가 없다. 캠페인 원본 폴더와 ZIP은 보관·백업 자료로 유지한다.

## 9. 2~3개월 후 자동 게시 검토 기준

다음 데이터를 운영판에서 확인해 자동 게시의 필요성과 위험을 평가한다.

- 발행 일정 준수율
- 채널별 게시 누락률
- 게시물 한 건당 운영 시간
- UTM 유입과 CTA 전환
- 게시 직전 수동 수정 빈도
- 채널별 문안 또는 이미지 수정 비율
- 플랫폼별 계정 권한과 API 안정성

수동 수정이 자주 발생하거나 플랫폼별 형식 차이가 크면 자동 게시를 보류한다. 반복성이 충분하고 누락 방지 효과가 명확할 때 네이버·Meta·Threads 연동을 별도 설계한다.

## 10. 오류 처리와 안전장치

- 게시 URL 없이는 발행 완료 상태를 저장하지 않는다.
- URL은 허용된 `http` 또는 `https` 형식만 받는다.
- 알림 실패는 문안·일정·게시 기록을 변경하지 않는다.
- 이메일 실패 원문이나 환경 변수 값을 관리자 화면에 노출하지 않는다.
- 상태 변경과 성과 수정 시 입력 검증을 수행한다.
- 외부 게시 URL과 운영 메모에는 고객 개인정보를 입력하지 않도록 안내한다.
- 관리자 인증이 없는 요청은 모든 콘텐츠 운영 API에서 차단한다.
- 기존 상담·결제 운영 데이터와 별도 테이블과 화면으로 분리한다.

## 11. 검증 기준

### 배포 자료

- 네이버 원고 6편이 현재 공식 원문과 일치한다.
- 카드뉴스가 편당 정확히 8장, 총 48장이다.
- 캡션과 대체 텍스트가 편당 하나씩 있다.
- Threads가 편당 4~5개다.
- 모든 UTM URL의 source, medium, campaign, content와 목적지가 정확하다.
- ZIP에는 해당 캠페인 자료만 포함되고 무결성 검사가 통과한다.

### 관리자 운영판

- 인증된 관리자만 목록·상세·수정 API를 사용할 수 있다.
- 9편과 모든 채널 작업이 중복 없이 초기 등록된다.
- 게시 URL 없이 발행 완료가 거부된다.
- 지연 상태와 요약 건수가 예정 시각에 맞게 계산된다.
- 모바일과 데스크톱에서 채널별 상태가 잘리지 않는다.
- 복사 버튼이 정확한 문안과 링크를 제공한다.
- 성과 값 검증과 테스트 데이터 제외가 동작한다.

### 알림

- 전날·30분 전·다음 날 알림이 KST 기준으로 선택된다.
- 동일 작업을 반복 실행해도 중복 이메일이 발생하지 않는다.
- 일부 발송 실패 후에도 나머지 알림이 처리된다.
- 실패가 운영판과 운영 모니터에 나타난다.
- 관리자 상세 링크가 올바른 콘텐츠와 채널 작업을 연다.

## 12. 범위 제외

- 네이버·Meta·Threads 자동 게시
- 외부 플랫폼에서 성과 지표 자동 수집
- 유료 광고 집행 또는 광고 예산 관리
- 외부 채널 계정 연결과 토큰 관리
- 신규 공식 블로그 글 작성

이 항목은 첫 2~3개월 수동 운영 데이터를 검토한 뒤 별도 설계와 승인을 거쳐 진행한다.
